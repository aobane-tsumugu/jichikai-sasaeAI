# 報告の写真

L-260とL-264に従い、届いた写真を報告の下書きから選び、提供側のContainerで顔を隠す。選択時に`waitUntil`で準備し、役員は待たずに戻れる。端末は範囲の追加と削除の座標だけを送り、検出と画素の変更は提供側で行う。修正と確認は必須にしない。「顔を隠さない」もサーバーで写しを再符号化する。

区のページと紙は、配った記録に結び付いた同じPNGを使う。元の写真は役員の認証の内側に保ち、公開の経路は元の写真を返さない。失敗・時間切れ・選び直し・取り下げの写真は配布から外し、報告を配る操作は止めない。日次の写しには画像と有効化設定を含めず、復旧後に写真を自動で再公開しない。

土台はPR #62の固定`ee658c9f88183ecdf080d07df1badfd186a3a566`のサーバー側。git操作をしない指示に従い、GitHub連携で指定範囲のソースを取得した。履歴のmergeとmainへの統合は未実施。旧ブラウザ検出のコードは取り込んでいない。表の追加は`0617_publication_photos.sql`。

## 実モデルの測定（2026-11-07）

公式の固定URLからYuNet 2023marを取得し、232589bytesとSHA-256を照合した。

`8f2383e4dd3cfbb4553ea8718107fc0423210dc964f9f4280604804ed2552fa4`

WindowsのPython3.13.8、OpenCV4.12.0.88、numpy2.2.6で、PR #62の`measure.py`と`evaluate.py`を実行した。生成された架空の成人12人の集合画像から、保存済みの縮小2条件（836×470、418×235）を使用した。**同じ12人の一つの場面であり、独立した24人や24枚ではない。** 実在の人の写真は使用していない。生成の来歴、画像hash、枠は`containers/face-mask/evaluation/measured-manifest.json`にある。

測定入力2枚、実モデルによる評価24枠、処理停止0枚。対応の判定はIoU0.3以上。検出を見落としても、近くの広い覆いに入る場合があるため、見落としと覆い不足を別々に記録した。手で修正した結果は測定に含めない。

この小標本は品質合格の証拠ではない。小さい顔の見落としが残る。正解枠はPR #62のAIによる目視入力で、人による確認は未了。照明・姿勢・遮蔽・別場面への一般化、実Containerの性能と外への通信制限、スマホでの操作性、実紙の見え方は測れていない。原寸PNGはGitHub連携で空の本文となり、blob取得も復号エラーになったため今回の評価に含めていない。

機械可読の結果は`evaluation/measured-result.json`、検出と覆いは`evaluation/measured-predictions.json`、実行条件とhashは`evaluation/measurement.json`。処理のprofileは`yunet-report-v2`。区の公開設定とWranglerのContainer設定は無効のまま。
