# 自治会運営AI支援サービス「SasaeAI」

SasaeAIは、自治会の役員が手元に持っている資料と、普段のLINEの連絡を、整理しないままの形で受け取り、行事や総会の準備、住民への知らせ、出欠の返事の集計、終わったあとの記録までを支えるWebアプリです。仕事を進めた結果がそのまま記録になり、次の年の役員はその記録から始められます。

目指しているのは、地域の助け合いの仕組みが、一部の人の能力や献身に頼らずに続くことです。

- **試す:** 審査員の方は、応募フォームの審査員欄にある案内から試せます。手元のパソコンでも動かせます（下の「試す」）
- **詳しく:** [設計](docs/DESIGN.md) ・ [手元で動かす手順](docs/RUNBOOK.md) ・ [デモの資料](fixtures/README.md)

この文書で「準備」と呼ぶのは、秋の収穫祭、総会、市からの依頼のような、ひとまとまりの仕事のことです。SasaeAIは、届いた資料や連絡を、この準備ごとにまとめます。

## 誰の、どんな困りごとか

使う人は、本業や家庭と並行して自治会を運営し、1、2年で交代する役員です。引き継ぎの手引きがないことが多く、教えてくれる人がいないこともあります。去年の案内は前の役員のパソコンのWordに、当番表はExcelに、決まったことは役員のLINEグループの投稿や電話のメモに散っています。新しい役員は、まずその資料がどこにあるかから探すことになります。

住民の側にも、届かない問題があります。紙の回覧は家族のうち一人しか見ないことが多く、若い人、加入していない世帯、来年の役員の候補にはほとんど届きません。それでも紙はなくせません。紙とWebを別々に作れば、役員の仕事は倍になります。

## なぜ必要か

全国の自治会・町内会等は、2023年4月1日現在で295,838団体あり、過去30年ほど29万から30万の間で大きく変わっていません（[国立国会図書館「調査と情報」No.1306](https://ndlsearch.ndl.go.jp/books/R100000039-I14019243) の表1。元は総務省「地縁による団体の認可事務の状況等に関する調査結果」）。一方、加入率を世帯単位で出している600市区町村の平均加入率は、2010年度の78.0%から2020年度の71.7%へ毎年下がっています（[総務省「自治会等に関する市区町村の取組についてのアンケート とりまとめ結果」](https://www.soumu.go.jp/main_content/000808317.pdf) 4頁。市区町村ごとの率の平均で、全国の全世帯の加入率ではありません）。

組織の数は変わらず、加わる世帯の割合は下がっています。仕事を少数の慣れた人の献身で回すやり方は、その人が交代した年に続かなくなります。SasaeAIは、引き継ぎが無くても、手元の資料と普段の連絡から仕事を進められることを目指しました。

## 登場する人と、使う画面

| 誰が | 使う物 | そこでできること |
|---|---|---|
| 役員 | 役員画面（IDとパスワードでログインして使うWebの画面） | 資料を送る、届いた物を見て直す、準備を始めて進める、住民へのメッセージを作って知らせる、出欠の返事を見る、終わりにする |
| 役員 | 役員のLINEグループ（自治会のLINEが入ったグループ） | いつもどおり写真や連絡を投稿する。投稿が、そのままSasaeAIに届く。SasaeAIからの知らせもここに届く |
| 実行委員と班長 | 実行委員と班長のページ（合言葉や一人用の入口で開くWeb） | 役員が知らせた当番表や配置図を読む。班長は自分の班の返事を見て、預かった回答票を写真で送る |
| 実行委員と班長 | 実行委員や班長のLINEグループ（自治会のLINEが入ったグループ） | 投稿が、役員のLINEグループと同じようにSasaeAIに届く |
| 住民と家族 | 住民向けのページ（ログインなしで読めるWeb） | 知らせを読む、出欠を返す、「一回だけ手伝う」に申し込む |
| 住民と家族 | 自治会のLINE（友だちに追加した人だけ） | 知らせが届く。個別のトークで質問や写真を送れる。受け取ったという決まった一言が返り、問い合わせは役員のLINEグループにも届く。返事は役員が書く |
| 住民と家族 | 紙（案内、回答票、掲示） | 紙で読み、紙で返事を出す。回答票のQRから、スマホで返事もできる |
| SasaeAIの運営者 | 運営者の画面 | 自治会を開く、自治会のLINEをつなぐ、ログインできない役員を助ける、問い合わせに答える |

使い方の説明は、それぞれの画面の見出しの下と「説明を読む」の中にあります。分からないときや、ログインできないときは、「SasaeAIに問い合わせる」から運営者に聞けます。

## 例えば、新しい役員が一年目に使うとき

1. **まず、手元の資料を十件ほど、持っている形のまま送る。** 最初の画面は、規約や会則、去年の総会の資料、年間の予定、世帯の名簿、役員の一覧、去年の案内や回覧、当番表、市から来た依頼などを、あるものだけ送るよう案内します。紙は撮って、Word、Excel、PowerPoint、PDFはそのまま、役員画面から送ります。パソコンなら画面にファイルを落としても送れます。役員のLINEグループには自治会のLINE（LINE公式アカウント）が入っていて、グループに貼った写真や連絡もそのまま届きます。十件ほど届くと、よくある自治会の例を仮に置いた一年の表が、少しずつこの自治会の予定に変わっていきます。資料の分類、ファイル名の付け直し、個人情報を消す作業は求めません。間違えて送った資料は、一件ずつ消せます。
2. **Claudeが読み、どの準備の資料かを見分ける。** 家計簿や年賀状のような関係のない資料は、どの準備にも入れずに残します（LINEの雑談の文は記録に残しません）。去年の資料の中身は参考として、今年決まったことは今年の中身として分けます。年が書かれていない資料を、今年の決定にはしません。
3. **中身が少しだけ違う二つの資料を、ファイル名で判断させない。** 「案内.docx」と「案内(1).docx」のように、どちらが新しいか分からない二つが届くと、Claudeが二つの中身を比べ、違う所と中の手がかりを挙げ、どちらが新しいかの推測を返します。ファイルに残る保存日や撮影日も並べます。去年の資料で、日付とClaudeの推測が同じ方を指すときはその方を使い、理由を残します。今年の中身が食い違うときと、どちらか分からないときは、比べた結果を添えて役員に一度だけ聞きます。
4. **届いた資料から準備を始める。** 読み終わった資料は、「秋の収穫祭の資料のようです」のように行事ごとにまとまって出ます。あとから見つかった資料も、続けて送れば同じように分かれます。そこから準備を始めると、資料が入り、やること（会場の予約、案内、手伝いの募集、当番、当日、報告など）が置かれます。去年の同じ行事の記録があれば、そのやることを引き継ぎます。記録がない初めての年は、届いた年間の予定や一般的な行事のやることから始めます。
5. **住民へのメッセージを作る。** 何を伝えるか（行事の案内や宣伝、手伝いの募集、連絡事項、終わった報告、実行委員と班長への連絡）と、どの準備のことかを選ぶと、準備に集まっている日時、場所、締切などが入った下書きが開きます。行事の案内では、出欠の返事を集めるかもここで選びます。返事で聞く欄（日を選ぶ、班、自由に書く）は準備ごとに足し外しでき、Webの返事と紙の回答票に同じ欄が出ます。役員は文を手で直し、チラシなどの画像を手元から足すか、届いた写真から選んで付けます。
6. **同じ中身から、住民向けのページと紙に出す。** どのメッセージも、送る前の確かめの画面を一つ通って知らせます。知らせる操作をすると、その時の中身が知らせたものとして残り、住民向けのページと印刷用の紙に同じ中身で出ます。自治会のLINE（画像と、題・日時・場所・返事のページのURLの短い文）で送るかは、この確かめの画面で、知らせるたびに役員が選びます。紙の回答票、電話、LINEで届いた返事も、Webの返事と同じ一覧に入り、二度数えません。
7. **変更、報告、そして次の年へ。** 雨で会場が変わるときは変更の連絡を出します。終わったら報告をほかのメッセージと同じ道で住民に送り、「終わりにする」と、使った資料、知らせた内容、返事の集計、報告が一か所に残ります。次の年の役員は、終わった行事の「終わったものをもとに新しく始める」から、その記録をもとに準備を始められます。

総会では、出席・委任・欠席を世帯ごとに、紙・Web・電話・LINEで同じ意味として数えます。委任の相手が空欄なら、推測で埋めず空欄のまま残します。役員会、当番表、市からの依頼も同じ形で扱います。

## 住民に届く道

住民向けのページは、普通のURLで、登録もアプリも要らずに読めます。配る紙の回答票には、スマホから返事ができるページのQRを刷ります。ページのURLをLINEで家族に転送すると、題と説明が出るようにしています。自治会のLINEを友だちに追加した人には、知らせが直接届きます。追加は住民の自由で、追加しなくても困らないようにしています。スマホを使わない人には、同じ中身の紙と掲示で届けます。

## 大事にした条件

SasaeAIは、次の条件を外さないように作りました。役員の仕事の実際から先に決めた条件で、技術の都合で曲げていません。

- **システムのための仕事を、役員に足さない。** 資料の分類、マスキング、保存先の判断、AIの読み取りの全点検、同じ内容の二重入力を求めません。
- **個人情報が混ざっている前提で受け取る。** 普段の資料には名簿や連絡先、当番を免除する事情が混ざっています。「個人情報は送らないで」と頼んでも、守られないか、使われなくなるだけです。受け取ったあとの保管、AIへの渡し方、見える範囲、消す方法は、SasaeAIの運営者が受け持ちます。
- **AIの推定を、決定として残さない。** 決めるのも知らせるのも人です。知らせた内容がそのまま記録に残り、記録のためだけの操作を別に置きません。
- **紙をなくさない。** 紙とWebとLINEは共通の情報から出します。伝え方の調整が要ることはありますが、日時や場所は一か所で直せばそろいます。紙、電話、LINE、Webの返事は同じ一覧で数え、二度数えません。
- **LINEは入口の一つで、前提にしない。** 限られた人向けの情報は、公開のリンクを持つだけでは読めません。
- **AIが働くのは、役員の準備の中だけ。** 住民はAIと話しません。住民向けのページ、Webの返事、紙と電話の返事の手入力、記録、印刷はAIを使わずに動きます。LINEで届いた文は、AIが出欠の返事かどうかを読んでから数えます。AIが止まっている間、その文は「届いたもの」に残り、役員が手で入れられます。
- **減るのは事務だけ。** 印刷、配る、設営、当日の運営、人との調整は残ります。

## Claudeの使い方

### 製品の中のClaude

| 仕事 | 使う物とモデル |
|---|---|
| 写真とPDFの中身を、決まった形の読み取りにする（Word、Excel、PowerPointは、古い形式も含めて、AIを通さずアプリが段落と表に取り出す） | Messages API、claude-sonnet-5-5 |
| 読み取った資料やLINEの文が、準備中のどれに当たるか、出欠の返事かどうかを、アプリが作った候補の中から選ぶ（候補に無い準備は作らない） | Messages API、claude-haiku-5-5 |
| 読み取りを準備の中身と照らし、変わったところと役員への質問を記録する | Managed Agents、claude-sonnet-5-5 |
| 中身が少しだけ違う二つの資料を、一組につき一度だけ比べる | Messages API |
| 住民へのメッセージ、当番表、議事録、報告の下書きを作り、役員の言葉の指示で直す | Messages API と Managed Agents、claude-sonnet-5-5 |
| LINEで送られた写真だけでは分からないことがあるとき、送った人に聞く一問の文を作る。写真が読めるかを確かめる | Messages API、claude-haiku-5-5 |
| 終わったものについての役員の質問に、同じ自治会の記録を根拠に答える | Messages API |

Managed Agentsには、MCPでアプリの五つの機能だけを渡します（list_open_projects、get_project_state、get_reading、write_change、write_question）。どの機能も、最初のメッセージで渡した受付の番号（コードではticket）を引数に取り、その一回の入力の範囲でしか読み書きできません。元の資料そのもの、知らせる操作、自由なデータベース操作、シェルは渡しません。資料の中の文は、AIへの指示ではなく資料として扱います。セッションごとに上限の金額を決めています。

照らす仕事は、読み取りと準備の状態を読み、変わったところを何度か書く、何手もかかる仕事です。Managed Agentsでこのやり取りをAnthropicの側で回し、アプリはセッションを始めて、終わったという知らせ（webhook）を受けてから結果を取り込むだけにしています。役員は資料を送ったあと画面を閉じてかまいません。知らせを取りこぼしても5分ごとに動く処理が拾い、止まったままの物は運営者の画面の「もう一度動かす」で動かし直します。

Managed Agentsが使えないときのために、同じ五つの機能をMessages APIで回す予備の経路も、自治会ごとに切り替えられるようにしてあります。ただし予備の経路では、何手ものやり取りを、資料を送ったときのWorkerの処理の続きとして回します。Cloudflare Workersは、画面に応答を返したあと（画面を閉じても同じ）続けられるのが30秒までなので、長い仕事は途中で切れることがあります。役員が資料を送って画面を閉じても、長い仕事が最後まで進むことが、Managed Agentsを使う理由です。

固定のAPIキーは置かず、Workload Identity Federationで、運営者が持つ署名鍵から短い期間のトークンを得ます。実装は[src/ai/](src/ai/)、処理と情報の境界は[設計](docs/DESIGN.md)にあります。

### 作るときのClaude

作った人間は一人です。何を目指すか、誰に負担を戻してはいけないか、どの案を採るかを本人が決め、Claudeには役割ごとに次の仕事を任せました。

- **考えを詰める:** Claude Code（主にFable 5.1）を壁打ちの相手にして、自治会の仕事を分解し、役員、住民、行政のそれぞれから案を点検させました。本人がAIの案を何度も退けて考え直した結果が、上の「大事にした条件」で、このリポジトリの[CLAUDE.md](CLAUDE.md)と[AGENTS.md](AGENTS.md)に、実装を担当するAIが守る規約として入っています。
- **進める（PM）:** Claude Code（Opus 5.5）が、実装の依頼を書き、戻ってきたコードを条件に照らして読み、mainへの統合、試験用の環境への配備、端から端まで動くかの確認、実際の画面を開いての確認を行いました。
- **画面を詰める:** 別のClaude Codeのセッションが、初めての役員が迷わない画面と言葉を設計し、直しました。
- **実装する:** 依頼を受けたCodex（手元とCodex Cloud）が、依頼に書かれたファイルの範囲で実装と試験を行いました。Claudeを依頼と点検と統合に回し、実装をいくつも同時に進めるためです。初期にはClaude Codeのクラウドのセッションも実装を担いました。担当の間の連絡は[Issue #1](https://github.com/aobane-tsumugu/jichikai-sasaeAI/issues/1)に残っています。

## 試す

- **ささえ台自治会:** 審査員の方向けです。案内とログインの情報は応募フォームの審査員欄でお知らせし、このREADMEには載せません。資料を送ってからAIが読み終わるまで、数分かかることがあります。
- **手元で動かす:** Node.jsとnpmを用意して、リポジトリのルートで次を実行します。

~~~sh
npm ci
npm run db:migrate:local
npm run dev
~~~

TypeScript、Cloudflare Workers、Hono、D1、R2で動き、画面はWorkersがHTMLで返します。AIを使うにはAnthropicの連携の設定、LINEを使うにはLINE公式アカウントの設定が別に要ります。AIなしでも、下書きを手で書いて知らせ、返事を受けるところまでは動きます。自治会と役員アカウントの用意、デモの資料を使った操作の順は[手元で動かす手順](docs/RUNBOOK.md)にあります。試験は`npx vitest run`で流せます。端から端まで操作する通しのスクリプトと、その確かめの範囲も、手順書の「確かめたこと」にあります。

## 続けて提供するための条件

自治会の普通の資料を、役員の前処理なしに扱う以上、保管、AIへの送り方、閲覧の範囲、バックアップ、削除、障害への対応、役員交代のときの支援は、SasaeAIの運営者の仕事になります。費用も、AIとサーバーだけでなく、これらを含めて地域が払える額にすることを条件にしています。保存された記録の一つでは、資料の読み取りと、読み取った内容を準備の中身と照らす処理（Managed Agents）の二つで約0.06ドルでした（AIの一部の処理だけで、一つの自治会の月の費用ではありません）。

ハッカソンでは、このリポジトリのために作った資料だけを使っています。
