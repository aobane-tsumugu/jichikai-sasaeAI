# 自治会運営AI支援（仮称）

自治会の行事や総会などを、準備から記録、次の担い手への引き継ぎまで、プロジェクトごとに扱う運営支援システムです。自治会の役員が持つ紙、写真、ファイル、短いメモをそのまま受け取り、既にある内容とのつながりや確認が必要な点を示すことを目指しています。

## 誰の、どの場面の、どんな困りごとを、どう変えるか

- **誰のために:** 本業や家庭と並行して運営を担い、短い周期で交代する自治会役員が使います。自治会の活動に関わるか迷っている人や、次の担い手にも情報が届くことを目指します。
- **どの場面で:** まず秋の収穫祭の準備を、去年の資料を探すところから、案内、出欠や手伝いの受付、変更、実施報告、来年に使う記録まで追います。
- **どんな困りごとを:** 資料や経緯が役ごとの手元に分かれ、口頭や電話の決定が残らず、紙と Web の案内や回答を別々に作り、集計し、役員交代で経緯が途切れます。
- **どう変えるか:** 役員が資料を事前に分類したり、個人情報を消したり、保存先を判断したりせず、手元の物を送るところから始められる設計です。AI が読み取り、既存のプロジェクトの内容と照合して、変わった点や問い、下書きを提示します。役員が判断し、直して配った内容を記録に残し、紙と Web の案内を同じ内容から作ることを目指します。

対象は事務の層です。印刷、仕分け、配達、回覧、掲示、集金、買い出し、設営と片付け、当日の運営、人との付き合い、本来の判断はなくなりません。操作を含めた負担の変化は測定していません。

- 操作の題材と順序: [fixtures/README.md](fixtures/README.md) の架空資料と、[docs/RUNBOOK.md](docs/RUNBOOK.md) の段 0〜6 を使います。既にあるデモ区を開き直す必要はありません。

役員画面は「今やること」「材料を送る」「新しいプロジェクト」「受け箱（件数）」から始めます。既存の行事は画面上部から続けられます。名簿、記録、区の設定などは「そのほか」にあります。

- 住民は公開ページから案内を読み、回答できます。「一回だけ手伝える募集」は、加入の手続きや世帯の登録をせず、名前と手伝える時間帯だけで申し込めます。募集を配っており、受付中の行事が対象です。公式 LINE の友だち追加は任意です。
- 役員会の記入欄と協賛先の一覧は、案内を配る前から「紙を印刷する」で使えます。配った案内や回答票は、配る画面の履歴から印刷します。
- 実行委員・班長の空間には、役員が配った文書と表が出ます。下書きを直すだけでは変わりません。空間を開く合言葉は用意され、班長には自分の班を見る専用 QR を渡せます。
- 世帯の回答は、役員の回答一覧にある「直す・消す」から訂正できます。締切も同じ画面で変えられます。閉じた仕事は「記録」で、地図・報告・配った物・答えの集計を読み返し、次の年の準備に使えます。

### ローカルで起動する

Node.js と npm を用意した環境で、リポジトリのルートから実行します。

```sh
npm ci
npm run db:migrate:local
npm run dev
```

Wrangler の開発サーバーが表示するローカル URL にアクセスしてください。区のデータと役員アカウント、Anthropic の Workload Identity Federation などの連携設定が無い環境では、デモ全体は動きません。秘密情報は `.dev.vars` などのローカル設定に置き、リポジトリや画面に記録しないでください。ローカルの通し動作はまだ確認できていません。

## Claude の使い方

### 運営支援システムの中

- 写真や PDF の読み取りには Anthropic Messages API を使います。Workers から原本を一回の呼び出しで渡し、決めた形式の読み取りを受け取ります。
- 読み取った内容をプロジェクトの状態につなぐ仕事には Claude Managed Agents を使います。役員が送った入力ごとに処理し、Workers が公開する MCP の五つの手を使います。手は「開いているプロジェクトを引く」「プロジェクトの状態を引く」「読み取りを引く」「差分を書く」「問いを書く」です。
- 読み取りや内容の接続には `claude-sonnet-5-5`、候補からプロジェクトを選ぶ単純な処理には `claude-haiku-5-5` を使います。製品内では Opus を使っていません。
- Anthropic の固定 API キーをアプリやリポジトリに置かず、Workload Identity Federation で短期間のアクセストークンを取得する構成です。
- AI は役員の準備作業を支援します。AI の推定を正式な決定にはせず、配布する内容や運営上の判断は人が決めます。配布後の公開ページ、回答、印刷は AI が止まっても使える設計です。

### 開発の進め方

Claude Code の Opus が PM として設計・割り当て・統合を進め、Claude の Sonnet が土台と AI の中心部分を実装し、Codex が画面、架空データ、各部品の接続を担当しました。役割を分けて進めた事実を記し、各機能が完成・検証済みであるという意味には使っていません。

- 架空のクロード区の「秋の収穫祭」に、架空のデモ資料 20 点（写真 10、Word 4、Excel 4、文字のファイル 2）を送り、AI が読み取り、プロジェクトの状態につなぎ、食い違いや決めることを問いとして出しました。
- 案内の下書きを AI が起こし、役員が直して配り（版 1）、区のページと印刷用ページに出ました。雨の問いに答えて AI が案内を書き直し、配り直しました（版 2）。区のページでは今の案内が先に出て、変更前の案内は畳まれます。
- 閉じる画面で、AI に報告と地図の下書きを頼み、公開する報告の下書きが画面に出ました。秋の収穫祭はまだ閉じていません。
- 確認用のプロジェクトを閉じ、記録の画面で地図と報告を読み、そこから来年の種を開いて、地図の日付が来年に置き直され、去年の地図に書いた頼んだ人、困ったこと、来年変えることが出ることを確かめました。役員の仕事と活動の紹介を区のページに載せ、公開の画面で読みました。
- 架空の別の区（scripts/walkthrough.ts と walkthrough-rest.ts）で、回答票の読み取りから集計、当番表と配置図、版 2 の配り直し、報告と閉じる、区の地図、記録を探す、記録に聞く、行政の依頼、帳簿、役員を足す、運用の費用の画面を通しました。
- 印刷用ページ（案内と回答票、班長への一枚、当番表と配置図、役員会の記入欄、協賛先の一覧）をブラウザの PDF にし、各紙が A4 一枚に収まることを確かめました。紙に刷って確かめたのではありません。

## 未確認と、実運用で見直す点

- 紙の配布先を世帯で選ぶことは、配る前の確認画面まで確かめ、配ってはいません。Web の回答を消すことは一件で確かめ、毎日の写しからも消えることは試験でだけ確かめています。
- 公式 LINE の一斉送信は、本物の住民や役員に送らないため、送っていません。
- 刷った紙での見え方と QR の読み取り、写真の顔を隠す部品、公式が入っている LINE グループからの受け付けは確かめていません。
- ローカルの `npm run dev` での通し動作は確かめていません。

実運用の前に、少なくとも本物の紙や写真での読み取り、個人情報を扱う委託と保管の根拠、権限と認証、バックアップと削除、障害時の対応、費用、LINE の運用を見直し、自治会ごとの合意を得る必要があります。効果や受容、加入率は測定していません。
