# 自治会運営AI支援サービス「SasaeAI」

自治会の役員が持つ紙、写真、ファイル、短いメモを受け取り、準備から案内、答えの集計、記録、次の担い手への引き継ぎまでを支える運営支援システムです。

## 誰の、どの場面の、どんな困りごとを、どう変えるか

- **誰のために:** 本業や家庭と並行して運営を担い、1、2年で交代する自治会役員が使います。引き継ぎの手引きや教えてくれる人がいないところから始める役員を想定しています。
- **どの場面で:** 行事や総会などの準備、住民への案内、出欠や手伝いの受付、変更の連絡、実施後の記録を扱います。最初に通した題材は、架空の自治会の秋の収穫祭です。
- **どんな困りごとを:** 資料が役ごとの手元に分かれ、電話や立ち話の経緯が残らず、紙とWebを別々に作り、役員交代で前の年の仕事が分からなくなることに向き合います。
- **どう変えるか:** 手元の資料を送ると、AIが読み、既にある内容につなぎ、変わったところ、質問、下書きを示します。役員が直して配った内容から紙とWebを出し、元の資料や経緯とともに次の年へ残します。

役員に資料の事前分類、個人情報の事前の消去、保存先の判断、AIの全件点検を求めない設計です。AIの推定を正式な決定にはせず、運営上の判断と配る操作は人が行います。住民は登録せずに案内を読んで答えられ、AIと話す必要はありません。

対象は事務の層です。印刷、仕分け、配達、回覧、掲示、集金、買い出し、設営と片付け、当日の運営、人との調整は残ります。操作を含めた負担の変化や、加入率への効果は測定していません。

### 架空資料で試す順序

実在の人や団体の資料は送らず、[fixtures/README.md](fixtures/README.md)にある資料を使います。公開ページを読むことと、データを保存して試すことは分けます。以下の保存・配布・閉じる操作は、独立したローカルの区で行います。詳しい準備と操作は[docs/RUNBOOK.md](docs/RUNBOOK.md)の段0〜6と「総会を手入力で一通り試す」にあります。既にあるデモ区を開設し直す必要はありません。

1. 公開ページで、配った案内と変更の知らせを読みます。以後はローカルの役員画面に入り、既にある行事の名前から段取りを開くか、「資料がないので、種類を選んで始める」で種類「行事」と名前を入れて「始める」を押します。
2. 試用する開催日と答え・手伝いの締切を、実行日より後の日に決めます。資料の「今年」は2026年で、2026年11月6日には開催日も締切も過ぎています。元の資料を書き換えず、試用の下書きに日時・締切を自分で入れます。名簿は行事を始めたあと、「最初の画面」→「ほかの場所」→「名簿」から入れられます。
3. 段取りの「資料を送る」から架空資料を送ります。AIの接続がないときは受け取った資料が保存されるところまでとし、読み取り・質問・AIの下書きができたとは扱いません。その場合も、自分で案内を書いて「保存して紙の見え方を見る」へ進めます。保存だけでは住民に配られません。
4. 「保存して配る内容を見る」で本文を読み、「配る相手や部数を変える」を開きます。公式LINEは「今回は送らない」を選んでから「配る」を押します。ローカルの区のページと、「印刷用ページを開く」から開く紙を見比べます。
5. 架空の出欠を送り、役員画面の「答えの一覧」と人数を読み、訂正を試します。一回だけの手伝いは「手伝いの募集」も配ってから申し込みます。実行委員と班長のページでは、役員が配った文書を読みます。
6. 自分で作った確認用の行事だけで、雨の変更を「今回は送らない」で配り、報告を手入力して「閉じて記録に残す」を押します。記録の「これをもとに新しく始める」で次の年へ進みます。
7. 総会は別に種類「総会」で始めます。「総会の招集」を手入力して配り、出席・委任・欠席の答え、委任欄のある紙、議案の資料・議事録、報告と記録を試します。この手順は架空の手入力を使います。使える資料と来歴はfixturesの説明を確かめてください。

共用のデモ行事を消したり閉じたりせず、確認用の行事と区別してください。自動の通し確認は別の確認用の区で行い、デモ区では実行しません。

今回の手順確認は、mainの02317dcを隔離したローカルWorkersと新しいD1/R2で動かし、ブラウザで行いました。AI・LINEなどの実設定を渡さず、アプリとブラウザの外向き通信を遮断しています。AIの代わりの読み取り結果は入れず、下書きと報告は手入力しました。紙のHTMLとA4のPDFまでの確認で、実AI・実LINE・刷った紙の確認ではありません。後続のmainの02a9cb9までに入った総会の公開文・紙・議事録を閉じる画面などは差分を読み、操作結果とは分けています。

### ローカルで起動する

Node.jsとnpmを用意し、リポジトリのルートで実行します。

~~~sh
npm ci
npm run db:migrate:local
npm run dev
~~~

Wranglerが表示するローカルURLを開きます。既存のローカルデータを残す場合は、別の作業場所と空のローカルD1/R2を使います。区のデータと役員アカウントは別に必要です。AIを使うときはAnthropicのWorkload Identity Federationなどの連携設定も必要で、この3コマンドだけでAIを含むデモ全体が使えるわけではありません。手入力で進める準備と今回の起動方法は[docs/RUNBOOK.md](docs/RUNBOOK.md)を参照してください。秘密情報はローカル設定や提供基盤の秘密情報の保管先に置き、リポジトリや画面に記録しません。

## Claudeの使い方

### 運営支援システムの中

- 写真やPDFの読み取りは、Anthropic Messages APIへの一回の呼び出しで、決めた形式の読み取りを得ます。
- 読み取った内容を行事の状態につなぐ仕事や、下書き、報告の作成にはClaude Managed Agentsを使います。入力や仕事ごとに短いセッションを開きます。
- エージェントが使うMCPの手は、開いている行事を引く、行事の状態を引く、読み取りを引く、差分を書く、質問を書く、の五つです。元の資料そのものや、配る操作は渡しません。
- 読み取りや下書きにはclaude-sonnet-5-5、候補から行事を選ぶ処理にはclaude-haiku-5-5を使います。製品内ではOpusを使っていません。
- 固定のAnthropic APIキーを置かず、Workload Identity Federationで短期間のアクセストークンを取得します。
- AIは役員の準備を支えます。配ったあとの案内、答え、印刷は保存済みの内容を使い、住民への返事をAIが作る仕組みにはしません。

処理と情報の境界は[docs/DESIGN.md](docs/DESIGN.md)、実装は[src/ai/](src/ai/)にあります。

### Claude Codeでの開発

Claude Codeを、設計の具体化、実装、検査、実機確認に使いました。現在はClaude Codeを使うPMが作業を割り当て、差分を読んで統合と配備を行います。Codexとdotも、割り当てられた範囲の実装、試験、文書を担当しています。

作業はファイルの担当を分け、作業枝と下書きのPRで返します。対象の試験と型の検査を行い、全試験は統合時に実行します。コードがあること、試験で通ったこと、実際の配備先で確かめたことを分けて記録しています。開発に使うAIと、製品内で資料を扱うClaudeは役割が異なります。

## 期間中に作った範囲

ハッカソン期間中に、このリポジトリのアプリと架空資料を新しく作りました。Cloudflare Workers、Hono、D1、R2を使うアプリに、次を実装しています。

- 役員の入口、区の設定、提供側の開設と問い合わせの受付
- 資料の受け付け、AIの読み取り、行事への接続、質問と下書き
- 段取り、運営メモ、案内や変更の配布、紙への印刷
- 紙・Web・電話などの答え、手伝いの受付、実行委員と班長のページ
- 公式LINEからの受け付けと通知の連携
- 報告、記録の検索、次の年への引き継ぎ、書き出し・写し・消去の処理

この説明の基準はmainの301eba6です。作業枝だけにある変更は含めません。種類別の段取りと下書きに加え、次の機能があります。

- **総会:** 出席・委任・欠席を紙・Web・電話・LINEから世帯単位で扱います。委任する相手の空欄は空欄のまま受け付け、成立の判断は代行しません。招集と回答票・委任状、議案の資料、議事録を扱い、配った回答票の追記は設定変更だけでは変わりません。
- **役員会と当番:** 役員会では前回の決定と未決を議題の資料に使います。当番は去年の表と今の名簿、期間を決めた免除から下書きを作り、人が担当を直して配ります。世帯ごとの当番・役の履歴を読み返せます。免除の理由は役員の範囲に置き、公開・実行委員のページ・配る紙へ出しません。
- **実行委員名簿:** 名前・役・連絡先を表として読み取り、人を足す・直す・外す操作ができます。当番表や進め方と一緒に実行委員と班長へ配り、配り直すまで配った名簿は変わりません。住民の公開ページには出しません。
- **転送と検索:** 公開したページには、転送時の題・説明・共通画像と検索エンジン向けの一覧があります。限定した内容、下げたもの、停止した区は一覧に出しません。役員は区内の記録を検索し、元の資料に戻れます。外部のサービスでの表示や検索結果への掲載は別の確認です。

これらは記録した時点の結果です。文書更新のために実機確認を再実行したものではなく、その後の変更や、あらゆる資料での読み取り精度を保証するものでもありません。

## 未実装・未確認と、実運用で見直す点

- **未実装:** 基準のmainには、公開写真の顔を自動で隠す部品がありません。写真は実行委員と班長のページおよび役員の範囲で扱い、顔を隠して公開できるとは案内しません。
- **実機で未確認:** 刷った紙の見え方とQRの読み取り、本物の手書きやスマートフォン写真での一般的な読み取り精度、公式LINEの一斉送信、LINEグループでの一連の操作。
- **一部だけ確認:** 世帯を選ぶ配布は配る前の画面までで、実際の配布は未実施です。消去の受付を確認した記録と、消去完了を確認した記録は区別します。日次の写しから実際のD1・R2へ戻す復旧は未確認です。
- **設定と実運用の確認が必要:** LINEやメールの入り方、問い合わせのメール送信などは連携設定に依存します。AIが使えないときの全体の運用も、手で進める処理があることと実機確認の完了を分けます。

実運用の前に、個人情報を扱う委託と保管の根拠、閲覧範囲、認証、保管期間、バックアップと削除、障害対応、LINEの運用を見直し、自治会ごとの合意を得る必要があります。会計の帳簿や決算は置き換えず、領収書の紙はこれまでどおり保管します。効果、受容、加入率は測定していません。

## 架空資料の来歴と再利用

デモとテストの資料は、このリポジトリのために作った自作の架空データです。実在の自治会、人、自治体、資料を元にしていません。写真風画像もプログラムで作った合成で、実際の撮影写真や手書きではありません。音声素材は同梱していません。

内容、生成方法、使用した字体、個別ファイルの来歴は[fixtures/README.md](fixtures/README.md)にあります。資料の内容・図・文・画像は、このリポジトリのApache License 2.0に従います。字体のファイルは再配布していません。

再利用時は架空の資料であることを明示し、合成画像を本物の写真や手書きの認識精度の証拠として示さないでください。これは誤解を避けるためのお願いで、ライセンスに追加の条件を課すものではありません。
