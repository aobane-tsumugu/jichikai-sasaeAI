# 自治会運営AI支援サービス「SasaeAI」

自治会の役員が持つ紙、写真、ファイル、短いメモを受け取り、準備から案内、答えの集計、記録、次の担い手への引き継ぎまでを支える運営支援システムです。

## 誰の、どの場面の、どんな困りごとを、どう変えるか

- **誰のために:** 本業や家庭と並行して運営を担い、1、2年で交代する自治会役員が使います。引き継ぎの手引きや教えてくれる人がいないところから始める役員を想定しています。
- **どの場面で:** 行事や総会などの準備、住民への案内、出欠や手伝いの受付、変更の連絡、実施後の記録を扱います。最初に通した題材は、架空の自治会の秋の収穫祭です。
- **どんな困りごとを:** 資料が役ごとの手元に分かれ、電話や立ち話の経緯が残らず、紙とWebを別々に作り、役員交代で前の年の仕事が分からなくなることに向き合います。
- **どう変えるか:** 手元の資料を送ると、AIが読み、既にある内容につなぎ、変わったところ、質問、下書きを示します。役員が直して配った内容から紙とWebを出し、元の資料や経緯とともに次の年へ残します。

役員に資料の事前分類、個人情報の事前の消去、保存先の判断、AIの全件点検を求めない設計です。AIの推定を正式な決定にはせず、運営上の判断と配る操作は人が行います。住民は登録せずに案内を読んで答えられ、AIと話す必要はありません。

対象は事務の層です。印刷、仕分け、配達、回覧、掲示、集金、買い出し、設営と片付け、当日の運営、人との調整は残ります。操作を含めた負担の変化や、加入率への効果は測定していません。

### 架空資料で試す順序

実在の人や団体の資料は送らず、[fixtures/README.md](fixtures/README.md)にある資料を使います。詳しい操作は[docs/RUNBOOK.md](docs/RUNBOOK.md)の段0〜6にあります。既にあるデモ区を開設し直す必要はありません。

1. 公開ページで、配った案内と変更の知らせを読みます。役員画面に入り、行事の名前から段取りを開きます。
2. 新しい確認用の行事で試すときは、去年の案内、名簿、当番表などの架空資料を送ります。資料がない場合は種類を選んで始めることもできます。
3. 届いた資料、変わったところ、質問を読み、今年決まったことを入れます。下書きを直し、紙の見え方を開きます。下書きを保存しただけでは住民に配られません。
4. 自分で作った確認用の行事で配る操作を試します。公式LINEは必ず「今回は送らない」を選びます。区のページと、配ったものの印刷用ページを見比べます。
5. 架空の答えを送り、役員画面の答えの一覧と人数を読みます。実行委員と班長のページでは、役員が配った文書と表を読みます。
6. 自分で作った確認用の行事だけで、変更の配り直し、報告、閉じる操作を試します。記録を読み、次の年の行事を始めるところまで進められます。

共用のデモ行事を消したり閉じたりせず、確認用の行事と区別してください。自動の通し確認は別の確認用の区で行い、デモ区では実行しません。

### ローカルで起動する

Node.jsとnpmを用意し、リポジトリのルートで実行します。

~~~sh
npm ci
npm run db:migrate:local
npm run dev
~~~

Wranglerが表示するローカルURLを開きます。区のデータと役員アカウント、AnthropicのWorkload Identity Federationなどの連携設定は別に必要です。この3コマンドだけでAIを含むデモ全体が使えるわけではありません。設定の手順は[docs/RUNBOOK.md](docs/RUNBOOK.md)を参照してください。秘密情報はローカル設定や提供基盤の秘密情報の保管先に置き、リポジトリや画面に記録しません。

## Claudeの使い方

### 運営支援システムの中

- 写真やPDFの読み取りは、Anthropic Messages APIへの一回の呼び出しで、決めた形式の読み取りを得ます。
- 読み取った内容を行事の状態につなぐ仕事や、下書き、報告の作成にはClaude Managed Agentsを使います。入力や仕事ごとに短いセッションを開きます。
- エージェントが使うMCPの手は、開いている行事を引く、行事の状態を引く、読み取りを引く、差分を書く、質問を書く、の五つです。元の資料そのものや、配る操作は渡しません。
- 読み取りや下書きにはclaude-sonnet-5-5、候補から行事を選ぶ処理にはclaude-haiku-5-5を使います。製品内ではOpusを使っていません。
- 固定のAnthropic APIキーを置かず、Workload Identity Federationで短期間のアクセストークンを取得します。
- AIは役員の準備を支えます。配ったあとの案内、答え、印刷は保存済みの内容を使い、住民への返事をAIが作る仕組みにはしません。

処理と情報の境界は[docs/DESIGN.md](docs/DESIGN.md)、実装は[src/ai/](src/ai/)にあります。

### Claude Codeでの開発

Claude Codeを、設計の具体化、実装、検査、実機確認に使いました。現在はClaude Codeを使うPMが作業を割り当て、差分を読んで統合と配備を行います。Codexとdotも、割り当てられた範囲の実装、試験、文書を担当しています。

作業はファイルの担当を分け、作業枝と下書きのPRで返します。対象の試験と型の検査を行い、全試験は統合時に実行します。コードがあること、試験で通ったこと、実際の配備先で確かめたことを分けて記録しています。開発に使うAIと、製品内で資料を扱うClaudeは役割が異なります。

## 未実装・未確認と、実運用で見直す点

- **未実装:** 基準のmainには、公開写真の顔を自動で隠す部品がありません。写真は実行委員と班長のページおよび役員の範囲で扱い、顔を隠して公開できるとは案内しません。
- **実機で未確認:** 刷った紙の見え方とQRの読み取り、本物の手書きやスマートフォン写真での一般的な読み取り精度、公式LINEの一斉送信、LINEグループでの一連の操作。
- **一部だけ確認:** 世帯を選ぶ配布は配る前の画面までで、実際の配布は未実施です。消去の受付を確認した記録と、消去完了を確認した記録は区別します。日次の写しから実際のD1・R2へ戻す復旧は未確認です。
- **設定と実運用の確認が必要:** LINEやメールの入り方、問い合わせのメール送信などは連携設定に依存します。AIが使えないときの全体の運用も、手で進める処理があることと実機確認の完了を分けます。

実運用の前に、個人情報を扱う委託と保管の根拠、閲覧範囲、認証、保管期間、バックアップと削除、障害対応、LINEの運用を見直し、自治会ごとの合意を得る必要があります。会計の帳簿や決算は置き換えず、領収書の紙はこれまでどおり保管します。効果、受容、加入率は測定していません。
