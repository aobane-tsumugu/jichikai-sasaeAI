# 通しの手順書: 秋の収穫祭を段 0 から段 6 まで

確かめる手が、架空の自治会の秋の収穫祭を、区を開く所から来年の入力になる記録まで通すための手順書です。送るファイルは [fixtures/](../fixtures/README.md) にあります。全て架空です。

画面がまだ無いので、設計書 07 の 3 章の言葉で書いています。「」は画面に出る言葉です。画面ができたら、作りながらここを実物に合わせて直します（末尾の「作りながら直す所」に、今分かっている迷いを置いています）。この手順書の「見えるはず」は、設計書と 06 から導いた物で、実物が違えば食い違いとして報告します。

## 0. 始める前に

### 0.1 通す物と場所

- ローカルの Workers: `npx wrangler dev`。鍵は `.dev.vars` に置きます（git に入りません。中身を画面にも記録にも出しません）。
- 固定: PM が指定した commit だけを通します。通した commit を証拠に書きます。
- 証拠: `docs/EVIDENCE/<固定>/` に、コマンド、出力、画面の写真（スクリーンショット）を段ごとに置きます。証拠の無い「通った」を書きません。
- 実装済み、正式未確認、実行失敗、対象外を分けて書きます。ローカルで通った事と、配備した staging で通った事は別に書きます。
- 本物の住民や役員に一斉送信しません。公式 LINE は検証用のアカウントだけを使うか、webhook の受け口に手で送ります。送信の枠（月 200 通）を使い切らないよう、段 2 と段 5 の一斉送信は検証用の友だちだけに向けます。

### 0.2 ブラウザの窓を四つ分ける

| 窓 | 使う画面 | 入り方 |
|---|---|---|
| A | 役員画面 | 役員のアカウント（段 0 で作る）でログイン。PC の幅 |
| B | 区のページ | ログインしない（別のプロファイルかプライベートの窓）。スマホの幅（375 px）でも見る |
| C | プロジェクトの空間 | 班長の専用 URL、または実行委員の合言葉。別のプロファイル |
| D | 運用の画面 | 提供側の ID とパスワード。段 0 だけで使う |

Word と Excel は役員のブラウザで展開して送る作りなので、窓 A は Chrome か Edge を使います。

### 0.3 役の分け

06 の例では、手の人（送る、直す、配る）は書記、決める人（可と言う）は会長と実行委員長です。役員画面は役で操作を縛らないので、確かめる手が一人で全部を操作してかまいません。決める人の可は、役員画面の外（電話、対面）で聞く物なので、この手順書では「可が出た体で進める」と書き、画面では何も押しません。

## 段 0: 提供側が区を開く（流れの前に一度）

誰: 提供側（窓 D）。その後、役員（窓 A）。

1. 窓 D の運用の画面に ID とパスワードでログインします。
2. 区を開きます。区の名前は「架空の区」。固定 URL と QR、最初の役員のアカウント、公式 LINE（検証用）、AI の鍵と agent の準備は、提供側のスクリプトで行います（作りながら、スクリプトの名前と引数をここに書きます）。
3. 最初の役員のアカウントを窓 A でログインして受け取ります。
4. 窓 A の「名簿」に `roster/加入世帯_2026秋.csv` を入れます。

見えるはず:

- 区のページ（窓 B）の固定 URL が開きます。まだ何も出していないので、空か「まだありません」に近い表示です。QR が出ます。

- 名簿を入れる時、列を選ぶ画面は出ません（先頭の行に「班」「世帯名」「氏名」があるので自動で決まる）。

## 作りながら直す所

- 版の数え方。06 は段 2 の配りを版 1、段 5 の配り直しを版 2 と書きます。段 4 の当番表と配置図の配り、段 6 の報告の配りを何番と数えるかは、作りが決めたら直します。画面では「出した物」と言い、版の番号を見せるかも作りが決めます。
- 田中の二つ。この手順書は、勝手に一つにしない、で書いています。実物が「同じ世帯かもしれません」と並べるか、別の答えとして数えるかで、数と文を直します。
- 市の通知の当て先。収穫祭のプロジェクトに当たるか、新しいプロジェクトを開く候補になるかは、実物に合わせて直します。
- 橋本の受付に時間の記入が無い所。受付の時間帯を当てるか、時間は未記入のまま出すか、実物に合わせて直します。
- 画面の名前。「プロジェクト・入れる」などは設計書の呼び名です。実物の名前に直します。
- 開設のスクリプトの名前と引数。段 0 に書きます。
