# SasaeAIを試す手順

役員が手元の資料から準備を進め、住民に知らせ、出欠の返事を集め、終わった記録を次の年に使う流れを試します。デモと試験の資料は、このリポジトリのために作ったもので、実在の自治会や人の資料ではありません。

この説明の基準はmainの`1ec276d1fd52f4fb2df5180e2c0e56a7b1aa9588`です。画面の操作はコードと照合し、実機で確かめた範囲は末尾の「確かめたこと」に分けています。

## 1. デモ用自治会の住民向けのページを開く

1. [デモ用自治会の住民向けのページ](https://jichikai.aobane-tsumugu.com/koukai/)を開きます。住民はログインや登録をせず、知らせた内容を読めます。
2. [審査員の案内](https://jichikai-guide.aobane-tsumugu.com/)を開き、試す自治会と役員画面の入口を確かめます。役員画面のIDとパスワードは応募フォームの審査員の欄で渡します。この文書には載せません。
3. 以後は案内された役員画面で試します。デモ用自治会と、審査用のささえ台自治会は別の自治会なので、知らせた結果は、その役員画面から開いた住民向けのページで確かめます。

共用の自治会に用意された準備を読むときは、「終わりにする」、消す操作、「住民向けのページから取り下げる」は使わないでください。保存や送信の操作を一通り試すときは、次の手順で、試しだと分かる名前の準備を別に始めます。自治会のLINEでは一斉送信せず、送る前の確かめの画面の「配る相手や部数を変える」で、毎回「今回は知らせない」を選びます。

## 2. 一年の予定から準備を始める

1. 役員画面のトップから「この自治会の一年を見る」を開きます。灰色の予定は、よくある自治会の例を仮に置いたものです。すでに準備している予定は、その準備を開いて中身を読めます。
2. まだ準備を始めていない予定を押し、その予定の今年の準備を始めるリンクを開きます。始める前の一行で、どのやることを置くかを読めます。準備の種類を選ぶ質問はありません。
3. 予定の名前が入っている場合は、分かれば「今年の当日（分かれば）」を入れ、名前の入った開始ボタンを押します。
4. 一年の予定にない準備を試すときは、トップの「新しく準備を始める」を開きます。「名前」に試しだと分かる名前を入れ、「だいたいの時期」を選び、「一年の予定に足して始める」を押します。時期が分からないままでも始められます。

やることは、去年の同じ準備の記録があれば今年の日に合わせて置き直し、なければ一年の予定ごとのやることを置きます。どちらにもないときは、知らせる、当日、まとめるの三つから始めます。やることはあとから足したり外したりできます。

ここからは、秋の収穫祭を例に読み進めます。共用の秋の収穫祭は読むだけにし、保存や送信の操作は自分で始めた準備で試してください。

## 3. 資料を送り、今年の中身と去年の参考を読む

1. 「資料を送る」を開きます。去年の資料を試す場合は、[デモの資料の一覧](../fixtures/README.md)から秋の収穫祭の資料を選びます。関係のない資料が混ざった場合や、中身が少しだけ違う二つの版を試す場合は、ささえ台自治会に送ったのと同じ[デモ資料25点](../fixtures/sasaedai/README.md)を、その送り方の順に送ります。実在の名簿や個人の連絡先は使いません。
2. 「カメラで紙を撮る」か「ファイルを選ぶ」で写真、PDF、Word、Excel、PowerPointなどを選び、「送る」を押します。パソコンでは、画面にファイルを落としても送れます。Wordは`.docx`と古い`.doc`、Excelは`.xlsx`と古い`.xls`、PowerPointは`.pptx`と古い`.ppt`を読みます。
3. 電話や立ち話の結果を入れる場合は「電話や立ち話で決まったことを書く」を開き、「決まったこと」に文を入れて送ります。通話そのものを録音する操作ではありません。
4. 受け付けたあともAIの読み取りは続きます。画面を閉じて、あとでやることの画面を開けます。受け付けたことと、読み取りや反映が終わったことは分けて確かめます。
5. 秋の収穫祭を開き、今年の中身と過去の資料の中身を読みます。去年の日時、担当、金額は、今年決まったこととは分けて扱われます。元の資料も開けます。
6. どの準備の資料か決まらなかったものは、「届いたもの」や読み終わった資料の画面から確かめます。必要な準備へ入れるか、新しく準備を始められます。
7. 間違えて送った資料や、要らないと決まった資料は、資料の画面の「この資料を消す」で一件ずつ消せます。準備や基本情報に入った資料も消せ、その資料から入った今年の中身、去年の参考、質問も一緒に外れます。

### 中身が少しだけ違う二つの資料を見る

「AIからの質問」があるときは、分かるものだけ答えます。質問が残っていても、下書きを直して住民に知らせられます。

二つの資料で内容が食い違ったときは、ファイル名だけでどちらを使うか決めません。違うところ、中身の手がかり、資料の日付とその出どころ、届いた日時、どちらが新しいかのAIの推測を読み、元の資料へ戻って比べられます。資料の日付が取れない場合は、不明のまま示します。見比べる画面には、保存してある比べた結果が並び、二つの元の資料へ行けます。画面を開くたびにAIを呼ぶことはしません。

去年などの過去の資料では、資料の日付と、中身から見たAIの推測が同じ資料を新しいと指すときだけ、聞かずにその資料を使います。日付が同じ、分からない、推測と合わない場合は質問になります。今年の中身の食い違いは、どちらを今年の中身にするか役員に聞きます。AIの推測を正式な決定とは扱いません。

### LINEから届いたものを見る

自治会のLINEを入れた役員のLINEグループに投稿された文や写真と、自治会のLINEへ個別に送られた文や写真も受け取ります。「届いたもの」ではトークと話題ごとに、送られた順で読めます。

送ってきた人の名前をLINEから取れた場合は、その名前で示します。取れない場合は、自治会の中でその人に付けた番号で区別します。

住民からの問い合わせは、中身が役員のLINEグループにすぐ届きます（月の送信の上限に近いときは、毎朝の知らせにまとめます）。返事は役員が書きます。AIは住民への返事を作って送りません。本物のLINEで受信を試す場合も、審査員の案内に従い、試しの文だけを送ります。

## 4. 住民へのメッセージを作る

1. トップ、または秋の収穫祭のやることの画面で「住民へのメッセージを作る」を開きます。
2. 「何を伝えますか」で、次の五つから選びます。

   | 選ぶもの | 伝えること |
   |---|---|
   | 行事の案内や宣伝 | いつ、どこで、何をするかと、来てもらう呼びかけ |
   | 手伝いの募集 | 当日の手伝いなど、一回だけ関われる仕事 |
   | 連絡事項 | 日時や場所の変更、持ち物、決まったこと |
   | 終わった報告 | 何をして、どうだったか |
   | 実行委員と班長への連絡 | 当番表や進め方を、実行委員と班長のページと紙で渡す（住民向けのページには載らない） |

3. 「どの準備のことですか」で対象を選び、「作る」を押します。やることの画面から来た場合は、その準備が選ばれています。自治会全体への連絡事項は「どの準備でもない」を選んで作れます。行事の案内では、出欠を聞くかも選べます。聞かない案内には、住民向けのページの「出欠を答える」の入口と紙の回答票が付きません。あとから下書きの画面の「出欠を聞く」「出欠を聞かない（知らせるだけにする）」で変えられます。
4. 準備に集まった日時や場所などが入った下書きを開き、題、本文、項目を手で直します。AIが文を整える間も手で直せます。AIを使えないときも、ここで書いて保存できます。
5. 画像を付けるときは「画像を付ける」で手元の画像を選ぶか、「届いた写真から選ぶ（役員の画面と、役員のLINEグループに届いたもの）」から選びます。選べる画像は一枚です。住民が個別に送った写真や、問い合わせとして受けた写真は、この候補には入りません。
6. 「保存して紙の見え方を見る」で印刷する本文を確かめます。「保存だけする」では住民には知らせません。
7. 下書きを読んで「送る」を押すと、保存して、送る前に確かめる画面が開きます。どのメッセージも、終わった報告も含めて、この一つの画面から送ります。押すと一度に起きること（住民向けのページに載る、自治会のLINE、紙の相手と部数）を読みます。載せない方がよい情報や、まだ決まっていないところが見つかった場合も、この画面に出ます。
8. 自治会のLINEに送るかは、この画面の「配る相手や部数を変える」で、「LINEで友だちに知らせる」か「今回は知らせない」を選びます。共用の自治会では「今回は知らせない」を選びます。LINEで送ったものは取り消せません。
9. 「住民に知らせる」を押します。すでに知らせた文書を直したときは、下書きの「直した内容を送る」から同じ画面に進み、「知らせ直す」を押します。

知らせた本文は、住民向けのページ、自治会のLINE、印刷する紙で同じ内容を使います。画像が出るのは住民向けのページとLINEで、紙には付きません。住民向けのページとLINEに載る画像は、この下書きで役員が選んだものです。届いた写真が勝手に住民向けに載ることはありません。

LINEの接続がない場合や送れなかった場合も、住民向けのページと紙は使えます。画面に出る送信結果を確かめてください。住民向けのページに載ったことだけで、LINEにも届いたとは判断しません。

## 5. 住民向けのページと紙を確かめる

1. 知らせたあとに「住民向けのページで見る」を開き、本文と選んだ画像を読みます。住民に見えるのは、知らせたときの内容です。
2. やることの画面から「紙を印刷する」を開き、案内や回答票の紙を選びます。日時、場所、返事の締切、渡し先を読みます。紙を実際に配る作業は役員や班長が行います。
3. 下書きだけを直して保存し、住民向けのページを読み直します。知らせ直すまでは、すでに知らせた内容は変わりません。紙を再び印刷するときも、知らせたときの内容を使います。

下書きの紙と、知らせたあとの紙は区別されます。下書きの紙にはQRコードと知らせた日を付けません。紙の表示を開けたことと、刷った紙の読みやすさやQRコードの読み取りを確かめたことは別です。

## 6. 出欠の返事を集める

1. 出欠を聞く案内を知らせたあと、住民向けのページから返事の画面を開きます。思いついた代表者のお名前、班、参加する人数など、画面にある欄を入れて送ります。住民の登録は要りません。
2. 役員画面に戻り、「出欠の返事を見る」から返事と集計を読みます。名簿を入れている場合は、まだ返事のない世帯も確かめられます。
3. 電話や紙の返事は「電話や紙の返事を手で入れる」から入れます。返事がまだない画面では「電話で聞いた返事を入れる」から開けます。間違えた場合は返事の一覧で直します。
4. 回答票は「回答票を撮って送る」から写真やPDFを送れます。読み取った返事を元の写真と比べ、直す必要があるところを直して入れます。人数を読めなかった返事は、不参加の0人として数えません。
5. 手伝いの申し込みがあれば、手伝いの一覧も読みます。世帯の返事にある手伝いと、手伝いだけの申し込みを合わせて読めます。

### 返事で聞くことを足す

出欠の返事の画面の「返事で聞くことを見る・足す」から、準備ごとに返事で聞く欄を足し、直し、外せます。型は、日を選ぶ、班（班の名前がある自治会だけ）、自由に書くの三つです。去年の回答票や案内に日や班の欄があれば候補に出ますが、押すまで足しません。足した欄は、住民のスマホの返事、電話の返事、返事の一覧、紙の回答票に同じ定義から出ます。紙の回答票に付けた印も読み取ります。日を選ぶ欄は日ごとの世帯と人数を数えます。欄を外しても、届いた答えは消しません。総会の返事には足しません。

AIが止まっている間も、Webの返事と手入力は使えます。LINEの文は、どの準備の返事か、返事かどうかをAIが判断してから数えるため、受け付けた記録があっても、返事の一覧に入っているとは限りません。手で補ったあとにLINEの処理が進んだ場合は、返事の一覧で二度数えていないか確かめます。

## 7. 実行委員と班長に必要なものを渡す

1. 秋の収穫祭のやることから当番表の下書きを開き、時間帯、持ち場、担当を直します。AIに下書きを頼むことも、手で直して保存することもできます。
2. 実行委員と班長のページの管理画面で「実行委員と班長が開けるようにする」を押します。合言葉と入口のQRコードが出ます。合言葉はそのときに一度だけ表示されます。
3. 当番表の下書きから知らせる内容を開き、「実行委員と班長のページに載せる」を押します。ここに載せる当番表は住民向けのページには出ません。下書きや担当を直しただけでは、相手に見える内容は変わりません。
4. 実行委員にはそのページのURLと合言葉、または一人用の入口を渡します。班長には、班を指定して作った「班長への一枚」を渡します。そのQRコードはその班長にだけ渡します。
5. 実行委員は「手元の紙を撮って送る」から書き込んだ紙を送り、班長は自分の班の返事を読んで「回答票を撮って送る」から回答票を送れます。

## 8. 変更を知らせ直す

1. 雨による場所の変更などが決まったら、その結果を資料として送るか、下書きの日時、場所、本文を手で直します。
2. 「住民へのメッセージを作る」で「連絡事項」と対象の準備を選んでも作れます。本文に変更後の日時と場所を入れ、紙の見え方を確かめます。
3. 雨の変更も、保存すると、案内と同じ送る前の確かめの画面に進みます。共用の自治会では、もう一度「今回は知らせない」を選びます。前回送らなかったことを、今回の選択の代わりにしません。
4. 「住民に知らせる」（すでに知らせた文書なら「知らせ直す」）を押します。連絡事項は送るたびに積まれ、前の連絡を畳まずに新しい順に並びます。日時や場所を変えた連絡なら、案内も直して知らせ直すと、住民向けのページと紙の案内も新しくなります。知らせたあとは、住民向けのページで変更の内容を読みます。以前の案内と取り違えないかも確かめます。電話での連絡や掲示の張り替えは、人が行います。

間違えた下書きは「前の下書きに戻す」を開き、「この下書きに戻す」で戻せます。戻しただけでは住民向けのページは変わらず、知らせ直す操作が必要です。住民向けのページから外したい場合は「住民向けのページから取り下げる」を使えますが、すでに送ったLINEは取り消せません。取り下げる操作は、自分で始めた確認用の準備だけで試してください。

## 9. 終わった報告と来年への記録を残す

ここは、自分で始めた確認用の準備で試します。共用の秋の収穫祭では行いません。

1. 実施後、やることの画面の「報告を書いて終わりにする」を開きます。報告の下書きはAIに頼むか、手で書きます。「住民へのメッセージを作る」の「終わった報告」からも作れます。
2. 報告は、ほかのメッセージと同じ「送る」から、送る前に確かめる画面を通して住民に送ります。LINEで送るかもそこで選びます。共用の自治会ではLINEへ送りません。
3. 「終わりにする」画面を開きます。報告の状態が出て、まだ送っていなければ「報告を見て送る」から報告の下書きへ戻れます。終わりにする操作では報告を配らず、送った報告の文を記録に残します。来年に残すことは、やることの欄に書けます。まだ当日が来ていない場合は、その案内と戻る道が出ます。
4. 終了後に変わることを読み、「終わりにする」を押します。返事の受付と実行委員と班長のページが終わります。手伝いだけの申し込みの名前と時間帯は消え、数は残ります。
5. 直したい場合は「終わりを取り消す」を使えます。消えた手伝いの申し込みの名前と時間帯は戻りません。
6. トップの「終わったものを見る」から記録を開き、やること、知らせたもの、報告、返事、元の資料を読みます。
7. 記録の上部にある、今年の準備を始める名前入りのリンクを開きます。「終わったものをもとに新しく始める」画面で名前、年、当日を入れ、「始める」を押します。やることを新しい日に合わせて置き直し、去年の記録はそのまま残します。
8. 過去の記録を探すときは「終わったものを言葉で探す」を開きます。「終わったものについてAIに聞く」では、答えと元の箇所を合わせて読みます。

## 10. 手元のパソコンで動かす

ここからは、手元のパソコンだけで自治会を開く人向けです。Node.jsとnpmを用意し、`scripts/*.ts`を直接実行できる環境で、リポジトリのルートから操作します。AIとLINEの接続がなくても、下書きを手で書いて知らせ、Webの返事を受ける流れを試せます。

1. 依存を入れます。

   ```powershell
   npm ci
   ```

2. ルートに`.dev.vars`をUTF-8で作り、1行に`名前=値`の形で書きます。`OPS_ID`と`OPS_PASSWORD`には自分で決めた値を入れ、`PUBLIC_BASE_URL`には`http://localhost:8787`を指定します。値をログや文書に写しません。`.dev.vars`はgitの対象外です。
3. ローカルのデータベースを作り、起動します。このコマンドはリモートのD1には適用しません。

   ```powershell
   npm run db:migrate:local
   npm run dev
   ```

4. 起動した端末をそのままにし、別の端末を同じリポジトリで開きます。ログインのリンクを書き出す`tmp/`を作ります。ここもgitの対象外です。

   ```powershell
   New-Item -ItemType Directory -Force tmp | Out-Null
   npm run open-ward -- --base http://localhost:8787 --keys ./.dev.vars --name "手元の自治会" --slug tameshi-local --first "試しの役員" --line-destination U00000000000000000000000000000000 --official-line-url https://example.invalid/line --credentials-out ./tmp/first-officer.txt
   ```

   LINEの送信先とURLは、ローカルで試すための仮の指定です。本物のLINEにはつながりません。`open-ward`は`--keys`で指定したファイルから運用の画面のログイン情報を読むので、`.dev.vars`を作るだけでなく、この引数も指定します。
5. `tmp/first-officer.txt`の一度だけ使えるリンクをブラウザで開き、IDとパスワードを作って役員画面にログインします。ファイルを共有したりコミットしたりしません。使い終わったら消します。
6. 上の2以降と同じ流れで、デモの資料か手入力を使って試します。LINEの選択は毎回送らない方にします。

AIへの接続がない間は、資料を受け付けて保存できても、読み取り、準備への結び付け、AIによる下書きは完了しません。AIを使う場合は、SasaeAIの運営者がAnthropicのWorkload Identity Federationと自治会ごとの接続を設定します。役員に鍵の設定を求める手順ではありません。

開発時の検査は次で行います。


## 11. 確かめたこと

通しは次のスクリプトで流します（`npm run walkthrough` のように、スクリプトの名前で呼べます）。走らせるたびに`docs/EVIDENCE/`に記録を一つ書きます。この記録はGitに入れません。

| スクリプト | 確かめる範囲 |
|---|---|
| [walkthrough](../scripts/walkthrough.ts) | ログイン、準備の作成、実ファイル4点の受付とAIの読み取り・反映、案内の紙、Webの返事、実行委員と班長のページ、当番表の紙、雨の連絡、終了と新しい年の開始 |
| [walkthrough-meeting](../scripts/walkthrough-meeting.ts) | 総会の招集、出席・委任・欠席、電話の返事、回答票、議事録と終わった記録 |
| [walkthrough-kinds](../scripts/walkthrough-kinds.ts) | 二回の役員会、翌年の当番、住民に知らせない行政への回答の資料、総会への決定の引き継ぎ |
| [walkthrough-rest](../scripts/walkthrough-rest.ts) | 回答票、記録の検索、AIへの質問と下書きの修正、当番の編集、役員への引き渡しなど。問い合わせの記録、予備の接続先、運用の画面のログイン情報の指定が無いときは、その項目を飛ばします |
| [line-sim](../scripts/line-sim.ts) | 自治会のLINEに届く文62通の受け取りと保存（本物のLINEは通しません） |

これらはHTTPとHTMLでの確かめです。ブラウザでの見え方、刷った紙、QRコードの読み取り、本物のLINEへの一斉送信は含みません。

`fixtures/`の紙の写真風画像は合成で、実際の手書きやスマートフォンで撮った紙ではありません。来歴は[デモの資料の一覧](../fixtures/README.md)で確かめられます。

SasaeAIが扱うのは、探す、作り直す、別々に作る、別々に数える、聞き直すという事務の層です。印刷や配る、設営、当日の運営のような物理の作業、人との関係、本来の判断は、これまでどおり人が担います。
