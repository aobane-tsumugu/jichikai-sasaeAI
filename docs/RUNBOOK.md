# 通しの手順書: 秋の収穫祭を段 0 から段 6 まで

架空の自治会「クロード区」で、2026 年の秋の収穫祭を準備する手順です。fixtures の資料と画像はすべて架空です。既にあるデモ区を使う時は、段 0 の開設を繰り返さず、発行されたアカウントで入ります。

画面名と経路は現行の `src/` に合わせています。今回の文書更新では公開ページの取得に失敗し、現在の配備先の文字との照合は未確認です。既存の実機確認は [STATE.md](STATE.md) と [EVIDENCE/](EVIDENCE/) を参照してください。この手順全体を再実行したとは扱いません。

以下の `{projectId}`、`{documentId}`、`{versionNo}` は画面に表示された値に置き換えます。

## 段 0: 区を開き、名簿を登録する

1. 既存のデモ区は `https://jichikai.aobane-tsumugu.com/demoku/admin/login` でログインし、手順 3 へ進みます。新しい区が必要な時だけ、提供側が `/ops/login` から「区を開く」を使います。既存の `demoku` を再登録しません。
2. 新しい区には名前、未使用の URL、最初の役員名を入力し「開く」を押します。発行された役員画面と初期アカウントを役員に安全に渡します。提供側の設定や認証情報はこの手順に書き写しません。
3. 役員画面の「そのほか」→「名簿」（`/demoku/admin/answers/roster`）から「名簿ファイル」に `fixtures/roster/加入世帯_2026秋.csv` を選び「名簿を読み込む」を押します。項目を選ぶ画面が出た時だけ、世帯名と班を選び「名簿を入れる」を押します。
4. 「班ごとの部数」と「世帯と班」が表示されます。名簿は役員用です。公開ページに出す内容ではありません。fixture の全 54 世帯の班別内訳との照合は、この文書更新では実機で未確認です。

## 段 1: 去年の資料を登録する

1. 続けるプロジェクトが既にあれば、その名前を開きます。新しく始める場合は役員画面の「新しいプロジェクト」（`/demoku/admin/projects`）で、種類「行事」、題、行事の日を入れて「開く」を押します。去年の記録から始める場合は段 6 の「来年の種」を使います。
2. 地図（`/demoku/admin/projects/{projectId}/map`）で次の仕事を見ます。必要なら「仕事を足す」、既存の仕事は「時期や担当を直す」から保存できます。すべての仕事を点検する操作は不要です。
3. 「材料を送る」（`/demoku/admin/intake`）で対象プロジェクトを選び、段 1 の去年の資料 7 点を送ります。「ファイルを選ぶ」で指定し「送る」を押します。Word / Excel の展開後も同じ送信が続きます。
4. 行事をまだ決められない市の通知は、「どのプロジェクトか」で「プロジェクトに当てず受け箱へ」を選んで送れます。「受け箱」（`/demoku/admin/inbox`）で読み取りや候補を読み、行事を選んで当てるか、新しい仕事を開きます。候補が出たことだけで正式な決定にはなりません。
5. 「入った物」で処理状況を読みます。受け付けた後は画面を閉じても処理が続きます。同じ物を送った時は「同じ物でした。」と出ます。
6. プロジェクト（`/demoku/admin/projects/{projectId}`）で材料、問い、今年の中身を読み、案（同じ URL の `/draft`）へ進みます。去年の参考と今年の内容を分けて読みます。公開する前の確認は段 2 の「配る内容の確認」で行います。

## 段 2: 今年の決定を記録し、公開する

1. 「材料を送る」から段 2 の 3 点を送ります。電話の結果など `.txt` の本文は「一行の文（電話や立ち話で決まったことなど）」に貼って送ります。
2. プロジェクトの「今年の中身」と「問い」を読み、判断が必要な問いに答えます。選択肢があれば押し、なければ「答え」を書いて「答える」を押します。「分からない」「後で」も選べます。
3. 案（`/demoku/admin/projects/{projectId}/draft`）で「案内」や「手伝いの募集」を選びます。「AIに案を起こしてもらう」を頼むか、自分で書き、「直した中身を保存」を押します。保存だけでは公開されません。去年の内容は参考として表示されます。
4. 「紙を印刷する」（`/demoku/admin/print/{projectId}`）では、配布前から「役員会の記入欄」と「協賛先の一覧」を使えます。紙に書いた決定は、紙の番号と一緒に撮って「材料を送る」から送ります。
5. 配る画面（`/demoku/admin/publish/{projectId}`）で、保存した案と「紙を配る相手」を選びます。「加入世帯」か「全戸（加入していない世帯も含む）」を選び、班ごとの部数を入れます。加入世帯の一部だけなら「世帯を選ぶ」で指定できます。名簿が無い全戸配布は「全戸に配る時の部数」を入れます。
6. 「公式 LINE」の欄があれば「今回は送らない」にして「配る内容を確認する」を押します。「配る内容の確認」にある本文、配る相手、混入の検査で見つかった所を読み、必要な所を案で直します。検査は個人情報をすべて見つける保証ではありません。送らない表示を読んで「配る」を押します。新しい材料が入った通知があっても、表示した案の内容で配れます。
7. 区の公開ページと `/demoku/p/{projectId}` で、今の案内と回答入口を読みます。配った物は配る画面の「これまでに配った物」に残ります。「印刷用ページ」から案内と回答票などを選びます（`/demoku/admin/print/{projectId}/{documentId}/{versionNo}`）。配布先の指定は公開ページには出ません。

## 段 3: 回答を集め、必要な所を直す

1. 世帯の回答は `/demoku/answer/{projectId}` で、世帯名、班、参加人数、任意の手伝いの希望を入れ「回答を送る」を押します。`Web回答.json` はファイルとして読み込まず、各項目を画面に手入力します。
2. 加入手続きと別に一回だけ手伝いたい人は、公開ページの「一回だけ手伝える募集」（`/demoku/help`）から行事を選びます。募集を配っており、締切前で開いている行事だけが対象です。`/demoku/help/{projectId}` で「名前」「手伝える時間帯」を入れ「手伝いを申し込む」を押します。世帯の登録は不要です。
3. 役員は回答画面（`/demoku/admin/answers/{projectId}`）で「電話の代理入力」を埋め「回答を入れる」を押します。電話メモを送るだけで回答として登録されたと扱わず、一覧で結果を読みます。
4. 紙の回答票は同じ画面の「回答票を読み取る」から送り、読み取りを確認・修正して「回答に入れる」を押します。元の写真は「回答票の原本を開く」で読めます。空間から班長が送った回答票も同じ集計に入ります。
5. 「回答の一覧」、参加人数、未回答と手伝いの一覧を読みます。「手伝いだけの申し込み」は別の一覧で、世帯の回答件数・参加人数には加算しません。当番表の案を作る材料になります。
6. 世帯の回答を直す場合は、一覧の世帯名の横の「直す・消す」を押します。名前、班、人数、手伝いを直して「直した回答を保存する」を押します。「保存せずに戻る」も使えます。誤入力の一件は「この回答を消す」で集計から外せます。原本や日次の写しを含む個人情報の削除依頼は、区の設定の「消す求め」で扱います。
7. 締切は同じ回答画面の「締切日（延長する場合は新しい日）」を入れ「締切を保存」で変えます。ここで指定した締切は案内を配り直しても変わりません。閉じた仕事の訂正は「報告と閉じる」から先に「開き直す」を押します。催促用の一覧は「印刷する」で印刷できます。
8. 公式 LINE から受け取った資料は「受け箱」で確認します。`LINE_webhook.json` は署名付き送信の手順ではありません。この手順では webhook への送信や本物の LINE の操作をしません。

## 段 4: 当番表と配置図を配り、空間で見る

1. 案の画面で「当番表」を開き、「AIに案を起こしてもらう」を頼むか、当番の担当を直して保存します。段 4 の当番表と配置図の写真は、「材料を送る」からプロジェクトを選んで送れます。
2. 空間の管理（`/demoku/admin/space/{projectId}`）には合言葉が用意されています。そのまま使うか書き換え、渡す相手のために安全に控えて「空間を開く」を押します。既に開いている空間の合言葉を変えると、それまでの招待や入室情報は使えなくなります。
3. 配る画面で当番表を「空間に配る」と、実行委員・班長向けに出ます。空間には配った時の文書・当番表・配置図・協賛先の表が出ます。役員が下書きや今年の中身を直している途中の内容は、配り直すまで変わりません。
4. 実行委員には空間の URL と合言葉を渡します。一人ずつの招待は「招待リンクを作る」、班長用は班を指定して「専用URLを作る」を使えます。班長にはその班の専用 URL だけを渡します。
5. 「班長への一枚」を印刷する時は空間を開き、区の設定で班の名前を入れてから「班長の専用 QR を作って印刷する」を押します。QR はその班長だけに渡します。班長は自分の班の回答を読み、「回答票を撮って送る」から写真または PDF を送れます。
6. 空間の「当番表や当日の紙を撮って送る」では写真または PDF を選び、「当番表や当日の紙を送る」を押します。受け取った紙は役員が読めます。配った文書の変更には役員の配り直しが必要です。

## 段 5: 雨天の変更を記録して再配布する

1. 雨天の判断の `.txt` を「材料を送る」の一行の文に貼って送ります。決まった内容や問いをプロジェクトで読みます。
2. 案の画面の「知らせ」には「雨天の知らせをすぐ用意」があります。定型文、行事名、変更後の会場、日時を入れ「定型文で知らせを作る」を押せます。定型文自体は `/demoku/admin/settings/templates` で保存できます。AI が止まっている時も自分で書いて保存できます。
3. 必要な所を直して「直した中身を保存」し、配る画面へ進みます。LINE の欄は「今回は送らない」を選び、確認画面で本文と送らない表示を読んでから「配る」を押します。公開側には今の案内が先に出て、「変更前の案内」から以前の内容を読めます。
4. 配る画面の「これまでに配った物」の「公開を下げる」で公開を取り下げられます。案の画面の「前の案」→「この案に戻す」は、以前の内容を新しい案として保存します。それを公開したい場合は、再び配る手順を進めます。LINE の送信はしません。

## 段 6: 実施報告を作り、記録から来年へつなぐ

1. 当日の書き込みのある紙は空間か「材料を送る」から送ります。領収書、レシート、会計メモは対象プロジェクトを選んで送ります。領収書一枚だけを支出全額とは扱いません。
2. 報告と閉じる画面（`/demoku/admin/close/{projectId}`）で「報告と地図の下書きを起こす」を頼めます。「公開する部分」「役員だけの部分」を直し「保存」を押します。地図の仕事の時期、名前、進み具合、頼んだ人、困ったこと、来年変えることも保存できます。
3. 「公開する部分」を保存すると、案の「報告」にも入ります。閉じる時にはこの公開部分が区のページに載り、公式 LINE には送りません。役員だけの部分は公開しません。閉じる前に報告を配る場合は、配る画面で本文を読んで「配る内容を確認する」へ進めます。報告には公式 LINE の送信欄はありません。
4. 「閉じて記録に残す」で仕事を閉じます。公開部分を保存していない時は、欄に表示された下書きが使われます。公開できない情報の指摘が出た時は公開部分を直します。デモの秋の収穫祭は閉じず、実機確認は Claude が確認用のプロジェクトで行います。閉じる時に手伝いだけの申し込みの名前と時間帯は消え、件数が残ります。閉じた後でも「開き直す」から直せます。
5. 役員画面の「そのほか」→「記録」（`/demoku/admin/archive`）で閉じた仕事を開きます。地図、報告に加えて「配った物」「答えの集計」、原本を読めます。配った時の内容と変更前の内容を引き継ぎに使えます。
6. 記録の「来年の種」で題、年、行事の日を入力し、「この地図を種に開く」を押します。去年の地図と状態を参考に、新しい年のプロジェクトが開きます。既存記録では、日付を次の年へ移したことが確認されています。

## 確認記録と残る確認

`npm run walkthrough` の通し確認では、段 2 で案内を公開し、配った文書の紙の HTML を開きます。案内に行事名・下書きの日時と場所があること、回答票に締切と班長か役員への渡し先があることを確かめます。段 3 では架空の回答を送ります。段 4 では当番表の紙の担当欄に名前が一人以上あること、段 5 では区のページの知らせが配った案内より上にあることを確かめます。見出しや紙を選ぶ画面だけでは通過にしません。内容が欠けたり順序が逆だったりした時は、その段が「停止」として `docs/EVIDENCE/walkthrough-*.md` に残り、終了コードは 1 になります。日時・場所が空で照合できない時も停止します。

本物の AI を使う通し確認は Claude が `kakuu` 区で行います。`demoku` では実行しません。紙の HTML の確認は、刷った実物の見え方や QR の読み取りの確認とは分けて記録します。

[STATE.md](STATE.md) と [EVIDENCE/](EVIDENCE/) には、架空資料の読み取り、案の公開・配り直し、別の確認用プロジェクトの閉じる・記録・来年の種、A4 の PDF、スマホ幅での表示、LINE の文・写真の受信などの実機記録があります。これらは今回の文書更新で再実行したものではありません。操作の負担、加入率、一般的な読み取り精度を測ったものでもありません。

現在の公開ページの文字との照合、刷った紙の見え方と QR の読み取り、本物の紙や写真での内容・読み取りは今回未確認です。公式 LINE の一斉送信も行っていません。新しく確認した時は、対象の画面と操作、結果を連絡網と確認記録に残します。

## 日次の写しから戻す

写しは DAILY の Cron で毎日作られます。区ごとに `snapshots/daily/YYYY-MM-DD.json` へ保存され、原本や配布記録などの正本を含みます。読み取り結果、実行記録、検索用の索引など、元の情報から作り直せる内容は含みません。原本ファイル本体は写しの JSON ではなく、同じ区の R2 にある原本のままです。

1. 戻し先の D1 と R2 を用意し、現在の `migrations/` を適用します。区のデータが空であることを確かめます。既存データへそのまま流すと重複や衝突になります。
2. 使う区の ID と日付を選び、次の形で R2 から JSON を取得します。`<ward-id>` と日付は実値に置き換えます。

   ```powershell
   npx wrangler r2 object get jichikai-sasae-staging/<ward-id>/snapshots/daily/YYYY-MM-DD.json --remote --file .\ward-snapshot.json
   ```

3. 取得した JSON を確認して SQL にします。

   ```powershell
   node scripts/snapshot-to-sql.mjs .\ward-snapshot.json .\ward-restore.sql
   ```

   この変換は、全行の `ward_id` が写しの区 ID と一致することを確かめ、表と行の順に `INSERT` 文を書きます。生成した SQL は個人情報を含むので、作業後に安全に消します。
4. 新しい空のデータベースへ実行します。

   ```powershell
   npx wrangler d1 execute jichikai-sasae-staging --remote --file .\ward-restore.sql
   ```

5. 件数と代表的なプロジェクト、役員アカウント、公開記録を確認します。別の D1 に戻す場合は、その区の原本 R2 も同じ区 ID のキーを保って復元してください。原本の写しも必要な場合は `originals` 表の `r2_path` を参照し、対象キーだけを同じ `WardBucket` の区内に戻します。

復元後に `readings`、実行記録、検索索引は空です。検索索引は記録の再構築処理で作り直します。日次写しと復元は、この作業区ではまだ実機で確認していません。
